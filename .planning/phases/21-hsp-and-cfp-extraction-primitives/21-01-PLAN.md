<resolved_decisions>

**1. File placement: `SmartRouter.Cli.Adapters` not `SmartRouter.Core`** (locked)

ROADMAP.md §Architectural Invariants ARCH-01: "Both new files (`HermesSessionExtract.fs`, `ContentFingerprint.fs`) live in `SmartRouter.Cli.Adapters` — NOT in `SmartRouter.Core`. Core receives no new files in v2.1." The design doc (`~/projs/smart-router-distillation/idea/hermes-session-without-modification.md` §2.2) shows the module header as `SmartRouter.Core.Routing.HermesSessionExtract` — **this is wrong for the project**. Use `module SmartRouter.Cli.Adapters.HermesSessionExtract` exactly.

**2. Module-level pre-compiled regex via `let private`** (locked by HSP-03)

HSP-03 requires "Regex is module-level pre-compiled (one allocation at module init; no per-request compilation overhead)." F# module-level `let private` bindings execute once at module init; this is the established F# idiom for one-time setup. The researcher explicitly recommends **NOT** using `RegexOptions.Compiled` because the JIT-emit cost outweighs the per-call benefit for this pattern (21-RESEARCH.md §Standard Stack > Alternatives Considered).

**3. Case-sensitive matching — no `RegexOptions.IgnoreCase`** (locked by HSP-03)

HSP-03 says "case-sensitive (matches Hermes' exact emission `Session ID: `)". `run_agent.py:5764-5766` always emits the exact string `Session ID: ` with that capitalization. The unit tests MUST include a guard: lowercase `"session id:"` returns `None`. The researcher flags this as an Open Question (21-RESEARCH.md §Open Questions item 4): HSP-04 lists 5 cases (a-e) but no explicit case-insensitive non-match case. Plan 21-01 adds it as the 6th test case.

**4. `Option.bind` not `Option.map`** (locked by F# type system)

`List.tryFind` returns `string option` (well, `Message option`); the inner regex lambda returns `string option`. `Option.map` would produce `string option option` — the F# compiler would reject the function signature `RouterRequest -> string option`. Use `Option.bind`. Researcher pitfall 6 (21-RESEARCH.md).

**5. `m'.Success` guard before `Groups.[1].Value`** (locked by .NET Regex semantics)

.NET `Match.Groups` returns empty Group on failed match, not an exception. Without the `if m'.Success` guard, `Groups.[1].Value` returns `""` and the function returns `Some ""` for a failed match — wrong. Researcher pitfall 8. Use the design doc §2.2 pattern: `if m'.Success then Some m'.Groups.[1].Value else None`.

**6. `\S+` in the pattern handles malformed-line case (e)** (locked by regex semantics)

`Session ID:   \n` (whitespace only after colon) does NOT match `^Session ID:\s*(\S+)` because `\S+` requires ≥1 non-whitespace char. The match's `.Success = false` and the function returns `None`. No additional code is needed to handle case (e); the regex is correct. Researcher pitfall 9.

**7. Insertion point in `SmartRouter.Cli.fsproj`** (locked by 21-RESEARCH.md §File Placement)

Place `<Compile Include="Adapters/HermesSessionExtract.fs" />` immediately after `Adapters/SessionStore.fs` (line 27) and before `Adapters/DecisionLogger.fs` (line 28). No within-project compile-order dependency (HermesSessionExtract only references `SmartRouter.Core.Domain`, which is in a different fsproj and already a `<ProjectReference>`). The choice is conventional — keep session-adjacent adapters together. Plan 21-02 inserts `ContentFingerprint.fs` immediately after `HermesSessionExtract.fs` so both new files form a contiguous Phase-21 block.

**8. No `testSequenced` wrapper** (locked by precedent)

`HardRulesTests.fs` is the test precedent: pure function, no `Console.SetOut`, no temp dirs, no DefaultHttpContext. Same shape as Phase 21 — synchronous pure function. No `testSequenced` wrapper. Confirmed in 21-RESEARCH.md §Open Questions item 3 and §Test Design.

    ```fsharp
    module SmartRouter.Cli.Adapters.HermesSessionExtract

    open System.Text.RegularExpressions
    open SmartRouter.Core.Domain

    // ── Module-level pre-compiled regex (HSP-03) ─────────────────────────────
    //
    // The pattern matches Hermes Agent's emission from `--pass-session-id` (see
    // ~/projs/smart-router-distillation/hermes-agent/run_agent.py:5764-5766):
    //
    //     timestamp_line = f"Conversation started: {ts.isoformat()}"
    //     if self.session_id:
    //         timestamp_line += f"\nSession ID: {self.session_id}"
    //
    // RegexOptions.Multiline (HSP-04 case d): ^ must match at the start of any
    // line in the System message content, not just at the start of the string.
    // The `Session ID:` line may appear on line 2 or later.
    //
    // Case-sensitive (HSP-03): no RegexOptions.IgnoreCase — `session id:` must NOT
    // match. Hermes always emits the exact capitalization `Session ID: `.
    //
    // `\S+` requires at least one non-whitespace character after the colon, so a
    // malformed line like `Session ID:   ` (HSP-04 case e) yields Success=false.
    //
    // Bound at module level via `let private` so the Regex is allocated once at
    // module init and reused across all calls — no per-request allocation
    // (HSP-03). RegexOptions.Compiled is intentionally NOT set; the JIT-emit cost
    // is not justified for this pattern at our request rate (21-RESEARCH.md).
    let private sessionIdRx =
        Regex(@"^Session ID:\s*(\S+)", RegexOptions.Multiline)

    // ── extractFromSystemPrompt (HSP-01 / HSP-02) ────────────────────────────
    //
    // Pure synchronous function. Applies only to the FIRST message with
    // Role = System (HSP-02); returns None when no such message exists or when
    // the System content contains no `Session ID:` line.
    //
    // Uses Option.bind (not Option.map) — see 21-RESEARCH.md Pitfall 6. The inner
    // lambda returns `string option`; with `map` the result would be
    // `string option option`, which the type signature rejects.
    //
    // The `if m'.Success` guard prevents returning `Some ""` for a failed match
    // (Regex.Groups returns an empty Group, not an exception). 21-RESEARCH.md
    // Pitfall 8.
    /// Extracts the Hermes `--pass-session-id` value from the first System message.
    /// Returns `Some captured-id` on a match, `None` when no System message exists
    /// or when no `Session ID: ` line is present. Pure — no I/O, no mutation.
    let extractFromSystemPrompt (req: RouterRequest) : string option =
        req.Messages
        |> List.tryFind (fun m -> m.Role = System)
        |> Option.bind (fun m ->
            let m' = sessionIdRx.Match(m.Content)
            if m'.Success then Some m'.Groups.[1].Value else None)
    ```

<risk_and_pitfalls>

Risks specific to Plan 21-01 (citing 21-RESEARCH.md §Common Pitfalls):

1. **Pitfall 6 — `Option.bind` vs `Option.map`**: If the executor types `Option.map` by reflex, the F# compiler rejects with FS0001 because the return type would be `string option option`. Action: use `Option.bind` exactly as shown.

2. **Pitfall 7 — `Groups.[1]` not `Groups.[0]`**: `Groups.[0]` returns the entire match (`"Session ID: abc123"`); `Groups.[1]` is the first capture group (`"abc123"`). Use `[1]`.

3. **Pitfall 8 — `m'.Success` guard required**: Without the guard, a failed match returns `Some ""` (Regex.Groups returns empty Group, not exception). The `if m'.Success then Some _ else None` pattern is mandatory.

4. **Pitfall 5 — `\n` not `\r\n` in test strings**: F# string literals with `\n` are LF (Unix). Hermes emits LF (Python f-strings on Mac). Test data must use `\n` only. If a future executor copies test data from a Windows editor with `\r\n`, the `\S+` group rejects `\r` and the captured value would not include `\r` — but the test assertion checks the exact id, which has no `\r`, so this would still pass. The pitfall is mostly precautionary on this Mac-only project.

5. **PITFALL-26 (CLAUDE.md / Expecto)**: Both the fsproj `<Compile>` entry AND the `rootTests` list entry are required. Missing either silently excludes the new tests. Verify both with the `grep -c` commands.

6. **TreatWarningsAsErrors=true**: Any compiler warning (unused open, shadowed binding, non-exhaustive match) becomes a build error. The recommended module body has no `match` expressions on DUs (no exhaustiveness risk), one `open` statement (`SmartRouter.Core.Domain`, used), and no shadowed bindings. Clean compile expected.
