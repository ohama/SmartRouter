## Tech Debt Inventory

### Carry-over (pre-v2.1, open)

**TD-1: TC-7 explicit ml-mode DI integration test absent**

The Phase 22 verifier recommended adding a test that constructs both DI pipelines (`Mode=selfrouting` and `Mode=ml`) and asserts `ISessionCascadeStats` resolves non-null in both. This was deferred from Phase 22 (TC-1..TC-6 were sufficient for phase acceptance). The current proof is structural: DI registration is unconditional before any mode branch in `CompositionRoot.fs`, and `GetRequiredService` in the call site guarantees startup failure if missing. This is sound but not an executable assertion.

Recommended fix: Add TC-7 in `tests/SmartRouter.Tests/SessionKeyCascadeTests.fs` using the `buildProvider` pattern from `StickyEscalationTests.fs` with `Routing:Mode=ml` config, asserting `GetRequiredService<ISessionCascadeStats>()` does not throw.

**TD-2: ModelsTests.fs IEmbedder errors (MODELS-01..03)**

Carry-over from v1.3. `ModelsTests.fs` uses `configureWithoutMl` which does not register `IEmbedder`; tests MODELS-01..03 are expected to error or be suppressed. Non-blocking for v2.1 which does not touch the ML registration path.

**TD-3: `configureServices` backwards-compat alias**

`CompositionRoot.fs` line 1369 comment states this alias may be removed after MODELS-01..03 migration. Blocked on TD-2.

**TD-4: Operator live-rig smoke test not yet run**

`scripts/smoke-hermes-session.sh` is operator-runnable (exits 0/1, no Hermes dependency, curl-driven against live router). The script itself is correct — bash -n exits 0, Tier 1/2/3 scope documented in header lines 23–29. The actual `./scripts/smoke-hermes-session.sh` run against the mlx_lm.server rig has not been logged. This is an operator action, not a code gap.
