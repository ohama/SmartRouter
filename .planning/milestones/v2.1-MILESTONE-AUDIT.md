### New (discovered by Phase 24 verifier + this re-audit)

- **TD-5** — `PITFALL-10` timing race in `QueueTests.fs`. Investigation:
  - Test asserts ordering `occupy → high1/2/3 → low1 (forced-low at K=3) → high4`
  - Failure mode: `Expected a (4) to be less than b (3)` — `high4` completes before `low1` because `Async.Sleep 30` barrier is insufficient when `LatencyFake(30)` on the occupy slot races with task enqueue
  - Isolation runs (5x): 60% failure rate (Pass/Fail/Pass/Fail/Fail in one trial; Fail/Fail/Pass/Fail/Pass in another)
  - Last code-relevant change: `fac58b2` (predates Phase 21); `d2ae1bf` (Phase 18) only cascaded `SessionId=""` to construction sites with no logic change
  - Production logic correct: `qd.FairnessPicksHigh==4` and `qd.FairnessPicksLow>=1` counter assertions always pass; only FIFO completion order assertion for `high4` is flaky
  - **Classification:** Test-side timing assumption flaw, NOT production concurrency bug. Pre-existing — not introduced or worsened by v2.1.
  - **Recommended fix (deferred):** Replace `Async.Sleep 30` with `Barrier` or `SemaphoreSlim` guaranteeing all 5 tasks called `EnqueueAsync` before occupy releases.
