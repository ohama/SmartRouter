# Requirements: Smart Router — v2.0 Self-Routing + Session-Aware

**Defined:** 2026-05-11
**Core Value:** Route every request to the model best suited to it — fast 35B for simple work, expensive 122B only when the task or signals justify it — while protecting 122B from concurrent overload.
**Milestone:** v2.0 (paradigm shift from v1.x ML routing to Hard Rules + 35B self-classify + sticky escalation)

## v2.0 Requirements

### Cross-cutting (Routing.Mode switch)

- [x] **MODE-01**: `appsettings.json:Routing.Mode` config key (string; default `"selfrouting"`); accepted values `"selfrouting"` | `"ml"`; invalid value fails startup with descriptive error
- [x] **MODE-02**: `CompositionRoot.configureRequestPipeline` branches on `Routing.Mode`: `"selfrouting"` registers selfrouting algorithm + SelfRouter + SessionStore; `"ml"` keeps v1.x ML classifier path intact
- [x] **MODE-03**: ML adapters remain compiled and DI-registered in BOTH modes; `RoutingAlgorithmRegistration.Algorithm` function branches on `Routing.Mode` so ML adapters are not invoked in the routing path when `Routing.Mode=selfrouting` (but `RetrainingService` BackgroundService still runs to accumulate hard cases)
- [x] **MODE-04**: README §7 documents the `Routing.Mode` key with both modes; CHANGELOG `### Changed` notes the v2.0 default flip

### Hard Rules Layer (Phase 17 — HR-*)

- [x] **HR-01**: `SmartRouter.Core/HardRules.fs` BCL-only module with `applyHardRules: RouterRequest -> RoutingDecision option`; pure function; case-insensitive `String.Contains(kw, StringComparison.OrdinalIgnoreCase)` over keyword list
- [x] **HR-02**: Default keyword list hardcoded: `["LLVM"; "MLIR"; "compiler"; "segfault"; "optimization"; "concurrency"]`; NOT exposed as config (operator safety mechanism)
- [x] **HR-03**: Hard Rules cascade position: Stage 0 — runs BEFORE explicit model override / explicit task / self-classify; any keyword match → immediate-122B
- [x] **HR-04**: `RoutingReason.HardRule` DU case added (7th); `DecisionLogger.formatReason` exhaustive 7-arm match → `"hard_rule"`; schema_version=1 unchanged
- [x] **HR-05**: Hard Rules applies to BOTH streaming and non-streaming branches (0ms keyword check; no chunk-shipped concern unlike quality fallback)
- [x] **HR-06**: Hard Rules wins over explicit model override AND explicit task field — `{"model": "35b", "messages": [{"content": "LLVM ..."}]}` routes to 122B with `routing_reason="hard_rule"`. (Updated during 17-03 from misleading original "bypasses" wording.)

### Session Store + Sticky Escalation (Phase 18 — SES-*)

- [x] **SES-01**: `SmartRouter.Core/Domain.fs` `RouterRequest` record gains `SessionId: string` field (empty string = no session, stateless path)
- [x] **SES-02**: `SmartRouter.Cli.Adapters.SessionStore` — `ConcurrentDictionary<string, SessionState>` + LRU eviction + 30-minute TTL
- [x] **SES-03**: `SessionState` record with `AddOrUpdate` 122B-wins merge function
- [x] **SES-04**: `CorrelationMiddleware` reads `X-Session-Id` HTTP header; stores in `HttpContext.Items[SessionIdKey]`; null-safe
- [x] **SES-05**: `ChatCompletions.fs` `mapWireToRequest` populates `req.SessionId` from `ctx.Items`; sticky cascade Stage 3 in routeRequest
- [x] **SES-06**: `RoutingReason.StickyEscalation` DU case (8th); `formatReason` arm `"sticky_to_122b"`; schema_version=1 unchanged
- [x] **SES-07**: Quality fallback writes session store on 35B → 122B substitution (Phase 14-16 integration point)
- [x] **SES-08**: TTL cleanup BackgroundService — PeriodicTimer (5min interval) iterates session store
- [x] **SES-09**: `appsettings.json:Routing.Session.{TtlMinutes, MaxEntries}` config keys

### 35B Self-Routing (Phase 19 — SR-*)

- [x] **SR-01**: `SmartRouter.Cli.Adapters.SelfRouter` — named `"selfrouter"` HttpClient pointing to `Upstreams.Model35B`; 5s timeout; 1 retry @ 200ms via AddResilienceHandler
- [x] **SR-02**: `prompts/self-router-prompt.md` operator-tunable template; `max_tokens=4-8`, `temperature=0`, `stream=false`
- [x] **SR-03**: `SelfRouteVerdict` DU 4 cases with safety-biased parser (ambiguous → `RouteUnsafe`)
- [x] **SR-04**: LRU cache by `prompt_hash` — `ConcurrentDictionary<string, CachedVerdict>` + monotonic access counter + bounded ~10000 entries
- [x] **SR-05**: `selfrouter_cache_hits` / `_misses` / `_call_count` / `_skipped` flat snake_case fields in `StatsWire`
- [x] **SR-06**: Streaming branch SKIPS self-classify — explicit `if req.Stream then skip SelfRouter` comment
- [x] **SR-07**: `RoutingReason.SelfRoute` DU case (9th); `formatReason` arm `"self_route"`
- [x] **SR-08**: `ChatCompletions.fs` cascade integration in non-streaming branch
- [x] **SR-09**: ML dormant integration test — `MlDormantTests.fs` verifies `Routing.Mode="ml"` boot path still wires ML classifier

### Hermes Agent Integration (Phase 20 — HMRS-*)

- [x] **HMRS-01**: `X-Session-Id` header opt-in (CorrelationMiddleware already specified in SES-04; session_id propagates through SES-05 → sticky escalation)
- [x] **HMRS-02**: Fallback fingerprint session key — `Session.FingerprintEnabled=true` (default `false`) derives session key from `RemoteIpAddress + User-Agent` SHA-256 prefix (16 hex)
- [x] **HMRS-03**: README §10 "Hermes Integration" rewritten for v2.0 — selfrouting paradigm description, X-Session-Id opt-in, fingerprint fallback caveats (NOT SAFE BEHIND REVERSE PROXIES → PROXY-01), HMRS-FUTURE-01 noted as future work
- [x] **HMRS-04**: CHANGELOG `### Added` mentions Hermes integration; `### Changed` notes paradigm shift; CHANGELOG promoted to `[2.0.0] - 2026-05-12`
